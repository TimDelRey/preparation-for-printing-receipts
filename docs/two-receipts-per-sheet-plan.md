# План: 2 квитанции на один лист

## Цель

Изменить генерацию `Receipts.xlsx` так, чтобы на одном листе размещалось не больше двух квитанций.

Теоретически на один лист может помещаться до трех квитанций, но для надежности печати, читаемости и меньшего риска наложения блоков фиксируем максимум две квитанции на лист.

## Базовые решения

- Максимум на листе: 2 квитанции.
- Смещение второго блока: уверенное, с запасом между квитанциями.
- Первый блок начинается с текущей разметки: строки `1-9`.
- Второй блок должен начинаться ниже первого блока с запасом, ориентировочно с `rowOffset = 10` или `rowOffset = 11`.
- Конкретное смещение нужно подтвердить визуальной проверкой итогового Excel-файла.
- Название листа формируется из текущих номеров участков из названий квитанций, соединенных через `-`.

Пример:

```text
уч.12-уч.13
```

Для одиночной последней квитанции используется текущее название:

```text
уч.12
```

## Важные ограничения Excel

- Имя листа Excel ограничено 31 символом.
- В имени листа запрещены некоторые символы: `:`, `\`, `/`, `?`, `*`, `[`, `]`.
- Так как план требует совмещать текущие названия через `-`, нужно добавить санитизацию имени листа.

## Текущее состояние кода

В проекте уже есть часть механики, которая пригодится для задачи:

- `PrintSingleReceiptAtOffset(...)` печатает single-квитанцию со смещением строк.
- `PrintDuoReceiptAtOffset(...)` печатает duo-квитанцию со смещением строк.
- `shiftCellRow(...)` умеет смещать координату ячейки на `rowOffset`.

Основной недостающий кусок: генератор шаблона сейчас рисует только один блок квитанции на листе.

## Архитектурный подход

Не использовать копирование строк Excel через `DuplicateRow`.

Причина: копирование строк в `excelize` может частично ломать ссылки, merge cells и связанные структуры. Шаблон квитанции маленький и полностью задается кодом, поэтому надежнее научить существующие функции рисовать шаблон с заданным смещением.

## План внедрения

### 1. Вынести чтение следующей квитанции

Сейчас `fragmentationReceips` одновременно:

- читает квитанцию;
- создает лист;
- печатает данные;
- удаляет обработанные строки из исходного файла.

Нужно разделить это на более мелкие операции.

Добавить функцию уровня service:

```go
func readNextReceipt(file *excelize.File) (*domain.Receipt, int, error)
```

Она должна вернуть:

- `nil`, если квитанций больше нет;
- `Receipt`;
- количество строк, которое нужно удалить из `Calc`: `1` для single, `2` для duo;
- ошибку, если чтение невозможно.

### 2. Собирать квитанции попарно

В `Run()` вместо схемы `одна итерация = один лист` перейти к схеме:

```text
прочитать первую квитанцию
если первой нет - закончить
прочитать вторую квитанцию
создать лист для одной или двух квитанций
удалить обработанные строки из исходного документа
повторить
```

Важно: удалять строки нужно после того, как квитанция прочитана и напечатана.

### 3. Добавить генерацию шаблона со смещением

Добавить функции в `pkg/domain/sample`:

```go
func DrawSingleSampleAtOffset(f *excelize.File, sheet string, receiptText ReceiptText, rowOffset int) error
func DrawDuoSampleAtOffset(f *excelize.File, sheet string, receiptText ReceiptText, rowOffset int) error
```

Они должны применять со смещением:

- высоты строк;
- стили;
- merge cells;
- заголовки;
- подвал;
- дату.

Ширины колонок можно выставлять один раз на весь лист.

### 4. Обновить печать данных

Для первой квитанции использовать `rowOffset = 0`.

Для второй квитанции использовать уверенное смещение:

```go
const secondReceiptRowOffset = 15
```

Данные печатать существующими функциями:

```go
domain.PrintSingleReceiptAtOffset(...)
domain.PrintDuoReceiptAtOffset(...)
```

### 5. Пересмотреть удаление строки для single

Сейчас `PrintSingleReceiptAtOffset` удаляет строку `8`, чтобы single-шаблон стал компактнее.

Для режима двух квитанций на листе это рискованно:

- блоки могут получить разную высоту;
- второй блок может съехать;
- смещение станет сложнее контролировать.

Рекомендуется для новой схемы не удалять строку внутри `PrintSingleReceiptAtOffset`

### 6. Название листа

Для пары квитанций:

```go
sheetName := first.SheetName() + "-" + second.SheetName()
```

Для одиночной квитанции:

```go
sheetName := first.SheetName()
```

После этого обязательно применить функцию безопасного имени листа:

```go
safeSheetName(sheetName)
```

Она должна:

- заменить запрещенные символы;
- ограничить имя 31 символом;
- избежать дублей.

### 7. Поддержать все комбинации

На одном листе должны корректно печататься:

- single + single;
- single + duo;
- duo + single;
- duo + duo;
- последняя одиночная квитанция.

### 8. Обновить тесты

Добавить тесты на новую раскладку:

- результат содержит меньше листов, чем количество квитанций;
- на первом листе есть первая квитанция в верхнем блоке;
- на первом листе есть вторая квитанция в нижнем блоке;
- шапка и подвал есть у обоих блоков;
- последняя одиночная квитанция печатается, если количество квитанций нечетное;
- имя листа строится из двух номеров участков текущих имен через `-`.

### 9. Визуальная проверка

После реализации нужно открыть или программно проверить итоговый `Receipts.xlsx`:

- оба блока находятся на одном листе;
- второй блок не пересекается с первым;
- подвал первого блока не налезает на шапку второго;
- single и duo выглядят стабильно в любых сочетаниях;
- печать в landscape остается корректной.

## Рекомендуемый порядок работ

1. Добавить тест, который фиксирует ожидание: две квитанции на первом листе.
2. Вынести чтение квитанции из `fragmentationReceips`.
3. Добавить генерацию шаблона со смещением.
4. Перевести `Run()` на попарную генерацию.
5. Добавить безопасное имя листа.
6. Проверить `go test ./...`.
7. Сгенерировать реальный `Receipts.xlsx` и визуально проверить раскладку.
